## 共通因数を探す

ビット長を見る。

```python
>>> [n.bit_length() for n in nums]
[1751, 1751, 1752, 1751, 1751, 1750]
```

全部ほぼ同じ長さ。1751 bit なので素因数分解は諦める。

次に6つの gcd を取ってみた。

```python
>>> math.gcd(*nums)
49691055669250699218925284312353622668301706461184
```

これを分解すると $2^{161} \times 17$ だった。
2のべきは単なる末尾の0なので、本質的な共通因数は **17** だけ。

実際、6つとも17で割り切れる。

```python
>>> [n % 17 for n in nums]
[0, 0, 0, 0, 0, 0]
```

## 17 が何なのか

17 を2進数にすると `0b10001`。

つまり $17x = x + (x \ll 4)$ である。
元の数に、自分自身を4ビットずらしたコピーを足している。

これが description の "weird crypto-scheme" の正体。
やっていることは**ゴースト（二重写し）**を重ねているだけ。

逆に言えば、17で割れば綺麗な元データが戻る。

## ビット列を画像として見る

17で割った値のビット長を見る。

```
1746, 1747, 1747, 1747, 1747, 1745
```

ここで気づく。$17 \times 103 = 1751$。
つまり元のビット列はちょうど **17行 × 103列**に収まる。

高さ17の画像だった。そして割る数も17。これは偶然ではない。

並べ方は以下。

- 列優先（column-major）
- 1列 = 17bit、MSB が先
- 画像は上下反転して格納されている

この通りに並べ直すとピクセルアートが出てくる。

```python
H = 17
s = bin(n // 17)[2:]
s = '0' * (-len(s) % H) + s
cols = [s[i:i+H] for i in range(0, len(s), H)]
img = [''.join(c[r] for c in cols) for r in range(H)][::-1]
```

試しに3行目（`WHY???`）を、**割る前**と**割った後**で比べるとわかりやすい。

## 読み取りで迷ったところ

フォントがメッセージごとに縦横比を変えて引き伸ばされている。
なので同じ文字でも行数が違う。ここが地味に面倒だった。

- `0b` の次の文字。輪郭だけ見ると `U` / `V` / `Y` が全部同じになる。
  `#...#` が8行続いて、1行で収束して、先端が2行。縦棒が短いので `V`。
  比較用に `WHY???` の `Y` を見ると、横幅2行に対して縦棒が6行ある。
  ソルバーはこの縦棒の比率で判定している。
- `DUHHH?` の `H` は本当に3個。`WHY???` の `?` も3個なので、
  この作問者は同じ文字を繰り返すのが好きらしい。

## まとめ

```
整数 → gcd で 17 を発見 → 17 で割ってゴーストを除去
     → 17bit ごとに列優先で切る → 転置して上下反転 → ピクセルアート
```

暗号というより、整数とビットマップの見方を変えるだけの問題だった。
`0b10001` に気づけば終わり。
