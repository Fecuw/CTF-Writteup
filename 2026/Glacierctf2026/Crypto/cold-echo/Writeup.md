# Cold Echo — Writeup

## flag

```
gctf{th3_1c3_k3pt_th3_r3c31pt}
```

ソルバ: `sage -python solver.py`（7 秒くらい）

## 問題の整理

`F_p`（`p = 17179869143`）上の次数 `d = 42` の秘密多項式 `P` があり、`P(1) = 1` に正規化されている。与えられるのは

- 42 個の trace：`P(u)·P(u⁻¹)`
- forward 1 個：`P(89)`
- `P` の係数を含むメッセージへの ECDSA P-256 署名

`P` の係数を当てて、署名が通るメッセージを作れれば flag が出る。

## 方針① trace から何が分かるか

`P(u)·P(u⁻¹)` という形がまず気になった。`x^d` を掛けると

```
Q(x) = x^d · P(x) · P(1/x) = P(x) · P*(x)
```

（`P*` は係数を逆順にした reciprocal 多項式）になるので、trace は `Q` の値を教えてくれていると考えられる。

- `Q` は次数 `2d = 84` で **回文（palindromic）**、`q_i = q_{84-i}`。だから未知の係数は `d + 1 = 43` 個だけ
- trace 1 個につき `Q(u) = reading · u^d` という一次式 → 42 本
- 正規化から `Q(1) = P(1)² = 1` → 1 本

43 本 / 43 未知数でフルランク → **`Q` は一意に決まる**。

ただし問題は、`P` と `P*`（とその因子の混ぜ合わせ）が同じ `Q` を作ってしまうこと。
trace だけでは「どの根が `P` 側か」が分からない。問題名の "echo" はたぶんこの反射のこと。

## 方針② Q を因数分解する

`F_p` 上で `Q` は **84 個の相異なる一次因子** に分解できた。
これは 42 組の逆数ペア `{r_i, 1/r_i}` になっていて、trace と矛盾しない `P` はペアごとに片方を選んだもの:

```
P(x) = c · ∏ (x − s_i),   s_i ∈ {r_i, 1/r_i}
```

候補は `2⁴² ≈ 4.4·10¹²` 通り。全部署名検証するのは無理なので、forward で絞りたい。

## 方針③ forward の値を「掛け算版ナップサック」として使う

`P(1) = 1` で `c` が決まるので `P(t) = ∏ (t − s_i)/(1 − s_i)`。
「全部 `s_i = r_i`」を選んだときの値を `base` とすると、ペア i を `1/r_i` に切り替えると `P(89)` は

```
w_i = f(1/r_i) / f(r_i),   f(s) = (89 − s)/(1 − s)
```

倍になる。なので欲しいのは `∏_{i∈S} w_i = P(89)/base` となる部分集合 S。

掛け算のままだと扱いにくいので、離散対数を取って足し算にしたい。ここで `p − 1` を見ると

```
p − 1 = 2 · 79 · 108733349
```

で十分 smooth（最大でも 1 億程度）。Pohlig–Hellman + BSGS で離散対数がすぐ取れる。
→ 条件が **mod `p − 1` の部分和問題（42 個）** になる。

42 個なら半分ずつ `2²¹` 通りの部分和を作る **Meet-in-the-Middle** で全解列挙できる。
見つかった解は **243 個**。ヒューリスティックの `2⁴² / (p−1) ≈ 256` とも合っていて妥当。

## 方針④ 最後は署名で一意に決める

243 個の候補それぞれについて

1. `P(1) = 1` に正規化
2. README の形式通りに receipt メッセージを組み立て
3. ECDSA P-256 / SHA-256 の署名を検証（Sage で手書き。公開鍵は SPKI の末尾 64 バイト、`(r, s)` は DER をパース）

とすると、**ちょうど1つだけ** 検証が通った。

## flag の復元

```
body = b64decode(flag_mask) XOR SHA256(b"cold-echo-flag-pad-v1\n" + message)[:len]
flag = gctf{ urlsafe_b64(body)（パディングなし） }
```

→ `gctf{th3_1c3_k3pt_th3_r3c31pt}`

## 振り返り

- `P(u)·P(u⁻¹)` から分かるのは `P·P*` まで。そこから `P` を戻すのは「逆数ペアのどっちを取るか」の 2 択 × d 回
- 評価値 1 個で `2^d` 候補を `2^d / p` 程度まで減らせるが、それが現実的に計算できたのは `p − 1` が smooth で離散対数が簡単だったから
- 署名は最後のフィルタとしてタダで使える
